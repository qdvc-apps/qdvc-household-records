## 1. User request

Please help me write a Python 3 GTK3 and GTK4 app called "QDVC Household Records" (technical name: `qdvc-household-records`). Its purpose is to help a household organise a folder full of PDFs which contain bank statements, insurance documents, rent receipts, and other such documents.

There should be 3 tabs at the top:

1. Home
2. Organiser
3. Setup

Let's talk about the **Organiser** tab first, as it is the heart of the app. This is a multi-pane master-detail view. Pane 1 is a list of **zones** (e.g., Freja Bank Statements, Freja Payslips, Ludvig Bank Statements, Ludvig Payslips, Shared Bank Statements, Shared Electricity, Shared Rent).

Pane 2 is a list of **accounts** for that zone. There should be a component in the user interface to easily add a new account to the currently-selected zone. Examples of zone-and-account combinations: Freja Bank Statements --> Bank of Atlantis, Atlantis Teachers Bank; Shared Electricity --> Powerplant Atlantica. Each account has:

- Name (e.g., Bank of Atlantis)
- Periodic or not
- If periodic: Cycle (days)
- Notes

Pane 3 is a list of documents for the currently-selected account. There should be a component in the user interface to easily add a new file into the currently-selected account as a document.

Pane 4 lists some catalogue information for the selected file. Each file has:

- Statement number
- Date issued
- Notes

Going back to Pane 2 for a moment: if an account is set to be periodic, with Cycle (days) configured, it could either be "Records are fresh" or "Records are stale". An account's records are "fresh" if `today's date` minus `cycle (days)` is chronologically prior to the newest `date issued` of any document within that account; otherwise the account's records are "stale".

Now let's talk about the **Setup** tab. Here, the user configures the **data folder** for the workspace. In the Organiser tab where the user can add documents to a workspace from the filesystem, these filesystem paths MUST be stored as **relative paths** based on the data folder. The user should NOT be allowed to add any file as a document if it is not within the data folder!

It is also in the Setup tab that the user configures the following lists:

- List of people in the household
- List of zoneblocks. Each zoneblock could be marked as individual, shared, or both. Each zoneblock also has a symbolic icon to be displayed in Pane 1 of the Organiser tab.

The combination of these lists gives us the zones in the organiser tab. For example, if people = [Freja, Ludvig], and if we have the following zoneblocks:

- Bank Statements (individual + shared)
- Payslips (individual only)
- Electricity (shared only)
- Rent (shared only)

Then we get the example zones that we had above.

Now let's talk about the **Home** tab. This is a classic "welcome to the workspace" kind of tab. For now I think it should just show a list of all the accounts that are fresh and all the accounts that are stale, each with a button to quickly jump to it in the organiser tab so that the user can have a look at that account.

This app follows https://github.com/qdvc-apps/qdvc-python-gtk-app-specification - deviations from this spec are allowed as long as there's a reasonable justification. As per the spec, the business data is stored in a workspace folder. Please make some sensible choices given the requirements listed above. Note that I have a preference for YAML over JSON for dict-like structures.

Please provide me with the codebase files in a ZIP file in every turn.

**Key design choices** (all within the spec's allowed deviations):

- **Zones are derived, not stored.** `Workspace.zones()` computes them from `people × zoneblocks` on demand. Accounts attach via a stable `zone_key` = `zoneblock_id::person_id` (or `::shared`), so renaming a person doesn't orphan accounts.
